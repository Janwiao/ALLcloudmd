2. 雲端名詞字典

不同服務常用不同名稱描述很接近、但不完全相同的功能。先看通用概念，再看各家自己的術語。

先記最重要的一句：Sync（同步）不等於 Backup（備份）。
Sync 的目標是「兩邊保持一致」，因此修改甚至刪除都有可能同步到另一端；Backup 的核心目標則是保留可恢復的副本。實際刪除與保留規則仍要看各家服務。

通用名詞

通用

Sync 同步

把本機資料夾和雲端資料夾連在一起，讓兩邊保持最新。多數桌面 Sync 是雙向：電腦改檔會上傳；雲端改檔也會回到電腦。

什麼時候用：每天工作的文件、圖片、專案資料夾，需要多台裝置保持一致時。

通用

Backup 備份

重點是「發生誤刪、硬碟故障、檔案損毀時還能恢復」。它不一定要像 Sync 一樣讓兩邊隨時完全相同。

注意：各家叫做 Backup 的行為不同，例如是否同步刪除、保留多久、是否有版本歷史，都要另看規則。

通用

Online-only 僅線上

檔案在檔案總管裡看得到，但完整內容主要放在雲端，不長期占本機空間；真正打開時才下載。

適合：雲端容量比電腦硬碟大很多，想「看得到全部、需要才抓」。

通用

Available offline 離線可用

雲端有一份，本機也保留完整副本。沒有網路仍能開啟；重新連線後再把變更同步上去。

代價：會占用本機硬碟容量。

通用

Cache 快取

為了讓常用雲端檔案開得更快，程式暫時留在本機的資料。Cache 通常可被系統清掉，不能把它當正式離線副本。

通用

Shared Link / Public Link 分享連結

產生網址給別人讀取或下載。別人下載造成的流量常會另外計入 Shared Traffic / Bandwidth。

通用

Transfer Quota / Bandwidth 傳輸額度

限制一定時間內能傳多少資料。它可以和 Storage 完全不同：有 1TB 空間，不代表有 1TB 或無限下載流量。

通用

Version history / Rewind 版本歷史／回溯

保留檔案先前版本或讓整個帳戶／資料夾回到較早時間點。這是誤覆蓋、勒索軟體、批次誤刪時很重要的功能。

Google Drive 常見名詞

Stream files｜串流檔案

Google Drive for desktop 的模式。檔案主要存在雲端，本機只在使用時下載並使用快取，因此很省硬碟空間。

適合可靠網路環境與「雲端很多、本機空間有限」的情境。

Mirror files｜鏡像檔案

雲端與本機各保留完整副本，所以檔案一直可離線使用，也會占用本機硬碟。

Google 官方特別指出，高頻寫入、影片剪輯、高解析圖片編輯等工作通常使用 Mirror 會更快。

Drive for desktop

Google 在 Windows / macOS 上的桌面程式，用來把 Google Drive 整合進檔案總管 / Finder，並提供 Stream、Mirror 等功能。

Shared drives｜共用雲端硬碟

Google Workspace 團隊功能。檔案屬於團隊空間，而不是單一成員個人帳號；適合公司、組織長期共同管理資料。

pCloud 常見名詞

pCloud Drive｜虛擬磁碟

在電腦建立一個虛擬雲端磁碟。檔案主要在 pCloud，預設不需要完整占用本機空間，需要時再讀取。

它比較像「雲端總倉庫入口」，不是把整個雲端完整複製到硬碟。

pCloud Sync｜同步

把你指定的本機資料夾和 pCloud 內某個資料夾綁在一起，進行雙向同步：任何一端修改，都會反映到另一端。

如果你要頻繁修改本機工作資料夾，應該看 Sync，而不是只把檔案放在虛擬 P: 磁碟。

pCloud Backup｜備份

選定桌面、文件、圖片等本機資料夾，自動持續上傳並更新到 pCloud。它和傳統「永不跟著刪」的離線備份不完全相同，因此仍要注意刪除與垃圾桶／版本保留規則。

Crypto Folder

pCloud 的加密資料夾概念，用來存放需要額外私密保護的內容。它和一般 pCloud Drive 區域的使用方式不同。

Dropbox 常見名詞

Online-only｜僅供線上存取

檔案顯示在 Dropbox 資料夾中，但完整內容放在雲端、不長期占本機空間。開啟時會自動下載。

Available offline｜離線存取

本機與 Dropbox 都有完整副本；沒網路也能打開。離線修改後，恢復連線時 Dropbox 會再同步。

Selective Sync｜選擇性同步

選擇哪些 Dropbox 資料夾要出現在這台電腦。適合公司或大帳號中有很多資料，但單一電腦只需要其中一部分。

File Request｜檔案請求

建立一個收件入口，讓別人把檔案上傳給你。用途和「我分享檔案給別人下載」相反。

MEGA 常見名詞

Transfer quota｜傳輸配額

MEGA 對下載與串流使用的傳輸額度。Free 帳戶最常遇到「空間還有，但 Transfer quota 先用完」。

Sync

MEGA Desktop 的資料夾同步功能，把本機與 MEGA 雲端資料保持一致。概念上和其他服務的 Sync 類似。

Backup

偏向保護本機資料夾的備份工作流。不要只因為名稱叫 Backup 就假設它一定是永久、不可刪除的歷史封存；仍需看 MEGA 當下版本保留與刪除規則。

GitHub 常見名詞

Repository / Repo｜儲存庫

一個 Git 專案的容器，包含程式碼、歷史紀錄與協作資訊。

Commit｜提交

把某一批變更記錄成一個版本節點，方便追蹤「改了什麼、何時改、誰改」。

Branch｜分支

從主要版本分出另一條開發線，讓新功能或實驗不必直接破壞 main。

Pull Request / PR

請求把某個 Branch 的變更合併進另一個 Branch，並讓團隊進行 Review、討論與檢查。

Release｜版本發布

把某個正式版本整理成發布頁，通常搭配版本號、說明與下載檔。

Asset｜發布附件

掛在 Release 底下讓使用者下載的 ZIP、EXE、Installer 等檔案。

Git LFS

Git Large File Storage。把大型二進位檔從一般 Git 歷史中抽離，用指標檔搭配專門儲存，避免 Repo 因大型檔案快速膨脹。

Cloudflare R2 常見名詞

Bucket｜儲存桶

R2 裡存放 Objects 的最上層容器，可以把它想成一個大倉庫。

Object｜物件

R2 裡真正儲存的一份檔案／資料，例如一張圖片、一個 ZIP、一個 Client 安裝包。

Key｜物件鍵

Object 的唯一名稱，例如 patch/2026/client.zip。R2 本質是平面結構，畫面看到的資料夾其實多半是 Key prefix 的視覺分組。

Egress｜出站流量

R2 把資料送到 Internet 的流量。R2 的重要特色就是 Internet Egress 不另外收費。

Public Bucket｜公開 Bucket

把 Bucket 的內容公開給 Internet 存取。正式環境通常會搭配自己的 Custom Domain。

Presigned URL｜預簽名網址

替私人 Object 產生「限時、限定操作」的網址，例如只允許某人 1 小時內下載，而不需要把 API 金鑰交出去。

S3-compatible｜相容 S3

R2 支援 Amazon S3 風格的 API，因此很多原本支援 S3 的 SDK、CLI、rclone 工具只要更換 Endpoint 就能使用。

Storage Class｜儲存類別

R2 目前有 Standard 與 Infrequent Access 等類別，用不同的儲存費、最低保存時間與 Retrieval 費交換成本。

Class A / Class B Operations

R2 對不同 API 操作類型的計費分類。簡單理解：除了「放多少 GB」，大量建立、列出、讀取 Object 也可能產生成本。

MediaFire 常見名詞

Ad-supported download｜廣告支援下載

免費使用者分享檔案時，下載者通常會先進 MediaFire 的下載頁，由廣告支撐免費頻寬模式。

5. 五個評分面向

個人使用

自己上傳、下載、保存、搜尋、跨裝置與日常管理的方便程度。

團隊使用

多人共同使用、權限、共同編輯、版本追蹤與協作流程。

頻繁修改

同一批工作檔每天反覆修改、儲存、同步、跨裝置更新時的穩定與效率。

公開分享

公開連結、Discord、論壇、網站下載，以及 Shared Traffic / Egress 的限制。

大容量收藏

數 TB 冷資料、歷史版本、素材、壓縮檔長期保存時的成本與體驗。

7. 容量與流量不是同一件事

Storage

倉庫有多大。只決定同時可以放多少資料。

Traffic / Egress

資料搬進搬出、或別人下載時產生的傳輸量。

例：10GB 檔案只占 10GB Storage；自己下載 3 次是 30GB；若 1,000 人各下載一次，則約產生 10TB 分享／出站流量。

9. 核心原則

個人 ≠ 團隊

自己好用，不代表多人權限與協作也強。

同步 ≠ 分享

同步很強的服務，不一定適合大量公開下載。

收藏 ≠ 頻繁修改

冷資料倉庫和每天反覆寫入，是完全不同的使用情境。

Storage ≠ Traffic

容量大，不代表公開頻寬大。
